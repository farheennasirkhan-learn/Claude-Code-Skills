Test Like It Will Be Used a Thousand Times

The danger is overfitting: a skill that works beautifully on your three examples and nowhere else.

When you test, watch for two failure modes:

Failure
What it looks like
The fix
Under-triggering Failure mode
Skill doesn't fire when it should
Sharpen and broaden the description
Over-triggering Failure mode
Skill fires on tasks it shouldn't
Tighten the scope and the description
Overfitting Failure mode
Works on your examples, fails on new ones
Generalise the instructions, remove brittle specifics
Use realistic, detailed test prompts. "Format this" tests nothing. "My boss sent a messy Q4 xlsx and wants a margin column" tests the real path.
