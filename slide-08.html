The Description Does the Triggering

The description is the single most important line you will write.

Claude decides whether to use a skill based almost entirely on its description. A perfect skill with a vague description never fires.

A strong description answers two questions: what the skill does and when to use it. Lean slightly pushy. Skills tend to under-trigger, so name the contexts explicitly.

Without
"Formats reports."
What does it do?
Never fires
With
"Generates a client status report using the STATUS framework. Use whenever an FDE needs a weekly update, delivery summary, or red/amber/green health check, even if they don't say 'status report' explicitly."
Clear job and clear trigger.
Fires when it should
